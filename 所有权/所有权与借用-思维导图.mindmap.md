# Rust 所有权与引用借用

## 0. 五条宪法

### 规则 1 · 唯一所有者
- 每个值有且只有一个 owner
- 变量离开作用域 → 值自动 `drop`

### 规则 2 · 同一时刻只能有一个所有者
- 赋值给别人 = **移动(move)**
- 原变量**失效**（编译期禁止使用）

### 规则 3 · 作用域即释放点
- 出作用域自动 `drop`，无需 free/GC
- `Drop` 后进先出（LIFO）
- 遮蔽(shadowing)：旧的同名变量立即 drop

### 规则 4 · 要么多个读，要么一个写
- 任意多个 `&T` **或** 恰好一个 `&mut T`
- 两者**不可共存**
- 目的：编译期消灭数据竞争

### 规则 5 · 引用必须始终有效
- 不能悬垂 dangling
- 引用不能比数据活得久

## 1. 为什么需要所有权

### 内存管理对比
- C/C++：手动 free → 悬垂/double free/泄漏
- Java/Go/Python：GC → 运行时开销、STW
- Rust：编译期借用检查 → **零运行时开销 + 内存安全**

### 借用检查器本质
- 编译期组件，**无运行时开销**
- 检查「别名 + 可变性」
- 有别名 → 不能写；要写 → 不能有别名

### 栈 vs 堆
- 栈：编译期已知、极快、`i32` `bool` `char` `&T`
- 堆：运行期可变、需指针跳转、`String` `Vec` `Box`
- **所有权管的就是堆内存的释放**

### String 内存布局
- 栈：`ptr`(8) + `len`(8) + `cap`(8) = 24 字节
- 堆：真正的字符数据
- `move` 只拷栈上 24 字节，**不拷堆数据**
- `len` 已用长度 / `cap` 已分配容量

## 2. 所有权三规则

### 规则一 · 每个值一个所有者
- `let s = String::from("hi");` s 是所有者

### 规则二 · 移动 move
- `let s2 = s1;` → s1 失效
- 函数传参 = move
- 函数返回 = move（所有权给调用者）
- 报错：**E0382** borrow of moved value
- 修复：借用 `&s` / `.clone()` / 元组返回所有权

### 规则三 · 出作用域释放
- `drop()` 自动调用
- 资源管理 RAII：文件、锁、socket

### 函数与所有权
- `fn f(s: String)` 夺走所有权
- `fn f(s: &String)` 只借用
- `fn f() -> String` 交出所有权
- 元组返回 `(usize, String)` 可「还回来」

## 3. 引用与借用

### 概念区分
- 引用 reference：`&T` / `&mut T`，一个地址
- 借用 borrowing：**创建引用这个动作**
- 引用不拥有数据

### 不可变引用 &T
- 可同时存在**多个**
- 只读，不能改
- 函数参数最常用

### 可变引用 &mut T
- 同一时刻**只能一个**
- 变量要 `mut`，引用要 `&mut`
- 独占访问权

### 为什么禁多个可变引用
- 数据竞争三条件：多指针 + 至少一个写 + 无同步
- Rust 直接禁掉，不需要运行时锁

### NLL 非词法生命周期
- 借用活到**最后一次使用**，不是代码块结束
- Rust 2018 起默认
- 新手最大误解来源
- 用完即可再借 → 很多「错误」写法其实合法

### 字段级拆分借用
- 不同字段可同时 `&mut`
- 先借整体就不能再借字段 → E0499
- 切片：`split_at_mut` 安全地一分为二

### Vec 经典陷阱
- `let first = &v[0]; v.push(4);` → **E0502**
- 真危险：push 可能扩容 → 旧引用悬垂
- `for x in &v { v.push(*x); }` 同样报错

## 4. 切片 Slice

### 形态与语法
- 字符串切片 `&str`，数组切片 `&[T]`
- `&s[0..5]` `&s[..]` `&s[6..]` `&s[..5]`
- 无所有权，只是引用+长度

### 类型对照
- `String` 拥有 / `&String` 借用
- `&str` 推荐作参数
- `Vec<T>` 拥有 / `&[T]` 推荐作参数

### 惯用法
- 参数用 `&str` 而非 `&String`
- 参数用 `&[T]` 而非 `&Vec<T>`
- deref coercion 自动转换

### 坑
- 越界索引 **panic**（运行时）
- 安全替代：`.get()` → `Option`
- 索引是**字节**，切在 UTF-8 字符中间会 panic

## 5. 生命周期 Lifetime

### 本质
- 就是「引用能活多久」的名字
- 不改变实际寿命，只给编译器**约束关系**
- 大部分情况编译器自动推断

### 悬垂引用
- `fn dangle() -> &String` → **E0106**
- 局部变量借出后出作用域 → **E0597**
- 修复：返回**拥有所有权**的值

### 标注语法
- `fn longest<'a>(x: &'a str, y: &'a str) -> &'a str`
- 含义：返回值活得 ≤ 输入中较短者
- 编译器推不出「跟谁一样长」时才需手写

### 省略三规则
- 规则 1：每个引用参数各得一个生命周期
- 规则 2：只有一个输入 → 赋给所有输出
- 规则 3：有 `&self` → self 的生命周期给输出

### 结构体持有引用
- `struct Excerpt<'a> { part: &'a str }`
- 实例不能比数据活得久
- 工程建议：优先放 `String`

### 'static
- `&'static str`：引用活到程序结束（字面量）
- `T: 'static`：类型内不含短命借用
- **不要一报错就加 'static**

## 6. Copy / Clone / Drop

### Copy 按位复制
- 赋值后原变量**仍可用**
- 有：整数、浮点、`bool`、`char`、`&T`、全 Copy 的数组/元组
- **`&mut T` 不是 Copy**
- 与 `Drop` 互斥

### Clone 显式深拷贝
- `.clone()` 拷堆数据，可能昂贵
- `Copy: Clone`，反之不成立
- 能解决报错，但要留意性能

### Drop 资源释放
- 出作用域自动调用，LIFO 顺序
- 实现 `Drop` 的类型不能是 `Copy`
- RAII：锁/文件自动释放

## 7. 智能指针

### Box<T>
- 堆分配、递归类型、trait object

### Rc<T> / Arc<T>
- 多所有者（共享只读）
- `Rc` 单线程 / `Arc` 多线程
- `Rc::clone` 只加计数，不拷数据

### RefCell<T> / Cell<T>
- 内部可变性：编译期检查 → **运行时**检查
- 违规在**运行时 panic**
- `Cell` 用于 `Copy` 类型

### 组合拳 Rc<RefCell<T>>
- 多所有者 + 可修改
- 优先用编译器检查，不得已才用

## 8. 常见报错速查

### 所有权类
- **E0382** moved value → 用引用 / clone / 元组返回
- **E0507** move out of borrowed content → clone / `mem::take`

### 借用类
- **E0502** `&T` 与 `&mut T` 冲突 → 让使用区间不重叠
- **E0499** 两个 `&mut` → 作用域隔离 / 索引 / `split_at_mut`
- **E0515** 返回局部变量引用 → 返回拥有型

### 生命周期类
- **E0597** does not live long enough → 延长所有者寿命
- **E0106** missing lifetime specifier → 手写 `<'a>` 或返回拥有型
- **E0716** temporary dropped while borrowed → 先 `let` 绑定

### 读报错技巧
- 关键句型：`occurs here` … `later used here`
- 编译器已标出「借用从哪开始、活到哪结束」
- 自问：这个借用的**最后一次使用**在哪？

## 9. 修复套路

### 套路 1 缩小借用范围
- `let first = v[0];` 复制代替借用

### 套路 2 调整语句顺序
- 先改再借，而不是先借再改

### 套路 3 作用域隔离
- `{ let r = &data; ... }` 提前结束借用

### 套路 4 索引 / iter_mut
- `for i in 0..v.len() { v[i] += 1; }`
- `for x in v.iter_mut() { *x *= 2; }`
- 新增元素：先 collect 再 extend

### 套路 5 mem::take / replace
- 从 `&mut` 中「换出」值
- `Option::take` 处理可空字段

### 套路 6 返回值设计
- 优先返回 `String` 而不是 `&str`

### 套路 7 clone / to_owned
- 最快但最贵，热路径慎用

## 10. 最佳实践

### API 设计
- 参数优先借用：`&str` / `&[T]`
- 需接管才按值收：`fn new(name: String)`
- 输入用 `&str`，输出用 `String`
- 方法三件套：`&self` 读 / `&mut self` 改 / `self` 消费

### 结构体设计
- 字段默认用拥有型 `String` `Vec<T>`
- 零拷贝解析才用 `&'a`

### 心法
- 别滥用 `clone()` / `Rc<RefCell<>>`
- 报错是**设计反馈**，不是敌人
- `unsafe` 只用于封装安全接口

## 11. 常见误区

### 所有权
- 「move 后 s1 变空值」→ 只是禁止使用
- 「所有赋值都是 move」→ Copy 类型是复制
- 「`&mut T` 也能复制」→ 它不是 Copy

### 借用
- 「借用活到代码块结束」→ 活到最后一次使用
- 「`&mut` 只能出现一次」→ 是不能**同时**存在
- 「借用就是复制」→ 只是给地址

### 生命周期
- 「报错就加 'static / clone」→ 先缩小作用域
- 「生命周期改变实际寿命」→ 只是标注约束

### 类型
- 「String 和 &str 差不多」→ 拥有 vs 借用
- 「len 是字符数」→ 是**字节数**，字符数用 `chars().count()`
